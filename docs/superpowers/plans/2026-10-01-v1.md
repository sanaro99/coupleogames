# CoupleOGames V1 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Deliver the agreed private two-partner game table with four playable games and a small animated black-cat host.

**Architecture:** A typed server game engine projects a different view for each authenticated seat. Socket.IO distributes validated state; SQLite persists sessions, active state and completed records. A React phone-first client uses HTML controls, a 2D drawing canvas and an optional procedural Three.js host/tabletop.

**Tech Stack:** Node 24+, React 19, TypeScript, Vite, Fastify, Socket.IO, SQLite, Three.js/React Three Fiber, Vitest, Playwright.

**Spec:** docs/superpowers/specs/2026-10-01-v1-design.md

## Global constraints
- Exactly two partner identities; no personal names/keys in tracked files or client defaults.
- Portrait phones primary; keyboard-operable laptop layout and reduced-effects equivalent.
- Server owns all secrets, scoring, turns and timers; persist one result per finished match.
- No cloud deployment in this implementation.

## Review focus
- Stale/repeated action after a reveal: reject rather than score twice (Task 1).
- Disconnect or restart during drawing: pause and restore time and strokes (Tasks 1–2).
- Third identity / forged seat / expired session: deny access (Task 2).
- Unicode, empty answers, giant payloads: normalize or reject with useful feedback (Tasks 1–2).
- 3D unavailable, hidden page, narrow screen: game remains readable/playable (Tasks 3–4).
